# MVU Status-Bar Conversion Guide

Load this reference **only** during onboarding (or an incomplete resume) when `campaign.json` has `"hasStatusCandidates": true` and `"hasStatus": false`. If `"hasStatusCandidates": false`, do **not** create `state.json` or `status/` and do **not** suggest running `hud.js`.

## 1. Read Candidates

Inspect `status/_raw_candidates.md`, generated by `init.js` from three possible sources:

| Candidate `Kind` | Origin | Conversion Strategy |
|---|---|---|
| `mvu` | `[initvar]`/`<initvar>`, `[mvu_update]`, `extensions.variables` / `dsh_mvu_conversion` | Preserve schema in `state.json`; rewrite `mvu_submit_update` rules into `status/rules.md` |
| `frontend-prompt` | Card/worldbook/preset instructions demanding `<user状态栏>`, `StatusBlock`, or end-of-reply status blocks | Extract narrative dynamic fields into `state.json`; write clear per-turn rules in `status/rules.md` |
| `frontend-regex` | `extensions.regex_scripts` capture/render patterns | Use regex labels/fields as hints; unify into `state.json` + `status/rules.md` |

## 2. Design `state.json` & `status/rules.md`

### `state.json` Layout & `hud.js` Display Mapping

Keep `state.json` clean, structured JSON (flat scalars or nested sections like `世界`, `user`, NPC objects). Avoid keys starting with `$` or `_` for visible stats (`hud.js` treats `$`/`_`-prefixed keys as internal metadata and hides them).

`hud.js` automatically maps values by shape:
- **Progress bars**: `"20/100"`, `"75%"`, or numbers `0–100` on gauge keys (`好感度`, `信任度`, `体力`, `理智`, `警戒度`, `hp`, `mp`, `san`, etc.).
- **Color chips**: Short scalar arrays (`["冷静", "警惕"]`, <= 10 items, <= 20 display width each).
- **2-line status cards**: `{ "状态": "...", "详情": "..." }` (or `{ "status": "...", "detail": "..." }`).
- **Diff highlights**: On every edit to `state.json`, `hud.js` automatically shows `(+5)`, `(-10)`, `↑`, or `+NEW`.

### Complexity Circuit-Breaker (Mandatory Transparency)

Do **not** blindly copy 30-field anatomical sheets or browser-JS formulas into `state.json`, and **never** drop fields silently:

1. **Static constants -> Lore only**: Unchanging physical/biographical constants (e.g., hair diameter, Achilles tendon length, arch index, eye color, height) do **not** belong in per-turn `state.json`. Keep them in `card/character.md` or `worldbook/` reference notes.
2. **Frontend JS / RNG formulas -> Drop**: Fields computed via frontend JavaScript formulas, HTML/CSS DOM scripts, or pseudo-math counters (e.g., `"JS公式算出的实时生理熵增系数"`) cannot execute in CLI text mode and cause model degradation. Omit them from `state.json`.
3. **Excessive trivial micro-fields -> Consolidate or Omit**: If a card demands dozens of per-turn organ/clothing micro-readings, consolidate into meaningful narrative fields (e.g., `状态`, `衣着`, `体温`, `好感度`, `当前心境`) and omit the rest.
4. **Document every decision**: Record kept dynamic fields, value bounds, and update triggers concisely in `status/rules.md`.

### Example `state.json` & `status/rules.md`

```json
{
  "世界": {
    "时间": "初秋夜晚 21:30",
    "地点": "旧城区小酒馆"
  },
  "角色状态": {
    "好感度": 45,
    "体温": "36.6°C",
    "当前心境": {
      "状态": "警惕试探",
      "详情": "暗中打量新来的客人，尚未放下戒备"
    },
    "状态标签": ["微醺", "警觉"]
  }
}
```

```markdown
# 状态栏更新规则 (`status/rules.md`)

每轮回复结束后，仅根据本轮实际剧情静默更新根目录 `state.json`：

- `世界.时间` / `世界.地点`：随场景推进或移动同步更新。
- `角色状态.好感度`（`0–100`）：友善互动 `+1~+3`，冒犯或违背承诺 `-2~-5`。
- `角色状态.体温`：常规约 `36.6°C`，仅在环境冷热变化或剧烈情绪波动时微调。
- `角色状态.当前心境`（`{ "状态", "详情" }`）：状态 2–4 字概括，详情用一句话说明心理动因。
- `角色状态.状态标签`：简短数组（`<= 6` 项），随饮酒、受伤、疲劳等增减。
- **已转入背景/省略项**：静态体测常数留于 `card/character.md`；前端 JS 熵增公式已舍弃。
```

## 3. Clean Leftover Inline Directives (Prevent Prose Pollution)

Before activating the status bar, remove every instruction telling the model to print an inline status block or `<thinking>`/`<mvu-status/>` inside chat replies:
1. Edit `card/character.md`, `worldbook/always.md`, and `card/greetings/*.md` (when status candidates originate from greetings) to strip the inline status-bar formatting blocks/templates (while preserving non-status character/lore facts!).
2. Check `preset/active.md`: if any enabled preset entry still instructs printing an inline status bar, write the cleaned entry text to `preset/overrides.json` keyed by its `identifier` (from `preset/source.json`), then run:
   ```bash
   node "<skill_dir>/scripts/preset.js" compile
   ```
   (Using `preset/overrides.json` + `compile` ensures future `preset.js toggle` calls preserve your cleanup.)
3. Update `campaign.json` (`"hasStatus": true`) and delete `status/_raw_candidates.md` (or run `node "<skill_dir>/scripts/init.js" --finalize-audit` alongside your onboarding audit to update `campaign.json`, clean temporary files, and sync `AGENTS.md`).
4. Optionally validate JSON formatting and layout in one shot:
   ```bash
   node "<skill_dir>/scripts/hud.js" --once --no-color
   ```

## 4. Onboarding Report Template (Send BEFORE Opening Scene)

Present this concise OOC conversion report **during onboarding BEFORE starting/rendering the opening greeting**, and wait for the player to confirm or pick a greeting before entering story prose. **Never** place OOC conversion notes in the same message as RP prose or inside ongoing RP turns.

````markdown
已完成状态栏适配与结构化拆分（已同步移除正文内联状态栏指令，避免污染剧情输出）：

- **已保留并转为实时追踪（`state.json` / `status/rules.md`）**：
  - `好感度`（0–100）、`体温`、`当前心境`（状态与内心细节）……
- **已转入背景设定或省略的字段**：
  - 静态体测常数（如发丝直径、跟腱长度、脚弓指数等 30 项固定数据）：不会每轮变化，已留作人物背景参考，不占用实时面板；
  - 依赖前端 JS 公式/脚本计算的字段（如实时生理熵增系数）：纯文本 CLI 环境下无法稳定执行前端运算，已舍弃以保证扮演稳定性。
  *(如你希望把其中某几项加回实时面板，随时告诉我即可补入 `state.json`。)*

你可以另开一个终端（或分屏）在当前目录运行以下命令实时查看状态面板：
```bash
node "<skill_dir>/scripts/hud.js"
```
````
